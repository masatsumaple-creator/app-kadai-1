# 家計簿アプリ 企画提案書

## 1. 背景・目的

講座課題として「1からアプリを作成する」ことが求められている。題材として家計簿アプリを選定する。家計簿アプリは CRUD（登録・一覧・更新・削除）、集計処理、認証、DB設計など、Webアプリ開発で学ぶべき要素を一通り含んでおり、課題として適切な規模感である。

## 2. 対象ユーザー

- 個人の日々の収支（収入・支出）を記録・把握したいユーザー（単一ユーザーでの個人利用を想定、ログイン機能なし）

## 3. アプリの概要

日々の収入・支出を記録し、カテゴリ別・期間別に集計・グラフ表示できるWebアプリケーション。

### 3.1 主な機能（案）

| # | 機能 |
|---|------|
| 1 | 収支データの登録（日付・金額・カテゴリ・メモ・種別） |
| 2 | 収支データの一覧表示・編集・削除 |
| 3 | カテゴリ管理（追加・編集・削除、初期カテゴリ用意） |
| 4 | 月別・カテゴリ別の集計表示 |
| 5 | グラフ表示（円グラフ・折れ線グラフなど） |
| 6 | 予算設定・予算に対する進捗表示 |
| 7 | データのCSV入出力 |
| 8 | 検索・絞り込み（期間・カテゴリ・キーワード） |

個人利用かつログイン機能は不要なため、上記すべてを実装対象とする。段階的に 1〜4（基本機能）→ 5〜8（拡張機能）の順で開発する。

## 4. 技術スタック（案）

ご指定の条件（フロントエンドはReact以外、バックエンドはJava以外、DBはPostgreSQL以外）を踏まえ、以下を採用する。

| レイヤー | 技術 | 理由 |
|---|---|---|
| フロントエンド | Vue.js 3（Vite） | Reactと異なるコンポーネント指向フレームワークで、学習効果が高く構築も容易 |
| バックエンド | Python（Flask） | シンプルな構成でREST APIを構築しやすく、学習コストが低い |
| DB | MySQL | PostgreSQL以外の代表的なRDBMSで、ORMとの連携実績も豊富 |
| API形式 | REST API（JSON） | フロント・バック分離構成のため |
| ORM | SQLAlchemy | Flaskとの連携が標準的 |

### 代替案（参考）

## 5. 全体アーキテクチャ（概要）

```
[ブラウザ (Vue.js SPA)]
        │ REST API (JSON / HTTPS)
        ▼
[Flaskサーバー (API)]
        │ SQLAlchemy ORM
        ▼
[MySQL データベース]
```

## 6. 開発の進め方

提出期限が未定のため、以下のフェーズに分けて進める。全機能を実装対象とするが、基本機能から段階的に構築する。

1. **フェーズ0**: 要件定義・設計（本ドキュメント群）
2. **フェーズ1（基本機能）**: 収支CRUD・一覧表示・カテゴリ管理・月別集計
3. **フェーズ2（拡張機能）**: グラフ表示・予算管理・CSV入出力・検索・絞り込み
